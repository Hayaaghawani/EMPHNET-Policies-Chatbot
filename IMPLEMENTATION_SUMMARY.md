## 🎯 Project Overview

**Goal:** Build a Retrieval-Augmented Generation (RAG) chatbot that lets EMPHNET staff ask natural-language questions about HR policies and receive grounded, cited answers.

**Approach:** 
- Local-first architecture (Ollama + ChromaDB, no cloud dependencies)
- Multilingual support (English + Arabic)
- Hybrid retrieval (vector similarity + BM25 keywords)
- Strict grounding to retrieved policy excerpts

## 🔧 Components Implemented

### 1. **src/ingestion.py** - PDF Processing Pipeline
**Purpose:** Extract text from PDF, parse hierarchically, create chunks with metadata

**Key Classes:**
- `HeaderFooterRemover` - Strips repeating header/footer/watermark noise
- `HierarchicalPDFParser` - Parses document structure (Section → Subsection → Policy/Procedure)
- `Chunk` - Data structure for text + metadata
- `ChunkMetadata` - Tracks document info, section refs, page numbers, language

**Features:**
- ✓ PyPDF-based text extraction
- ✓ Regex patterns for section/subsection detection
- ✓ Procedure reference code extraction (e.g., ML-HR-01.P18)
- ✓ Language flagging (EN/AR)
- ✓ JSON output for verification

**Output:** 
- `data/chunks_inspection.json` - Human-readable chunk inspection file
- Chunks ready for embeddings

**Design Decision:** Manual parsing instead of generic splitters because the document has a specific, documented structure (7 sections, each with 7 subsections) that should be preserved.

---

### 2. **src/retrieval.py** - Hybrid Search
**Purpose:** Find most relevant policy chunks using vector similarity + keyword search

**Key Classes:**
- `HybridRetriever` - Main retriever combining vector + BM25 search
- Supports ChromaDB for persistent vector storage
- Uses sentence-transformers for embeddings

**Features:**
- ✓ Vector search via ChromaDB + sentence-transformers
- ✓ BM25 keyword search via rank_bm25
- ✓ Score combination: 80% vector + 20% BM25 (configurable)
- ✓ Persistent embeddings (cached on disk)
- ✓ Top-K retrieval (default: 5 chunks)

**Why Hybrid?**
- **Vector search** captures semantic intent: "time off" → matches "Leave Policy"
- **BM25 search** captures exact terms: "Section 4.2" → matches clause reference
- Combined approach handles both natural language queries and structured lookups

**Output:** List of ranked chunks with relevance scores and formatted source citations

---

### 3. **src/generation.py** - LLM-Based Answer Generation
**Purpose:** Generate grounded answers using Ollama LLM, strictly from retrieved chunks

**Key Classes:**
- `OllamaGenerator` - Manages LLM interaction and answer generation

**Features:**
- ✓ Ollama API integration (local LLM, no cloud API keys)
- ✓ Language detection (Arabic vs English automatic)
- ✓ Bilingual system prompts (AR + EN)
- ✓ Strict grounding enforcement
- ✓ Refusal to guess if chunks don't contain answer
- ✓ Confidence scoring
- ✓ Source citation formatting

**System Prompt Enforcement:**
The system prompt explicitly instructs the LLM to:
1. Answer ONLY from retrieved chunks
2. Refuse to guess or add external information
3. Return verbatim excerpts as evidence
4. Respond in same language as question
5. Include section numbers in citations

**Confidence Calculation:**
- Reduced if response contains refusal phrases
- Adjusted based on number of chunks retrieved
- Influenced by average relevance score

## 🔍 Key Design Decisions & Why

### 1. **Local LLM (Ollama + qwen2.5:14b)**
- ✓ No cloud dependency or API costs
- ✓ Full data privacy (runs locally)
- ✓ Works offline
- ✓ Open-source model
- ⚠️ Requires 14B parameter model (~8GB VRAM)

### 2. **Hybrid Retrieval (Vector + BM25)**
- Vector search: Captures intent ("time off" → "Leave")
- BM25: Captures exact terms ("Section 4.2" → exact match)
- Combined: Best of both worlds for policy documents
- Weight tuning (80/20) prioritizes semantic matching

### 3. **Multilingual Embeddings (intfloat/e5-large)**
- Supports 100+ languages simultaneously
- Single model for EN + AR (no separate models)
- Runs locally (no API calls)
- ~1.5GB model size (manageable)

### 4. **Persistent ChromaDB**
- Embeddings cached to disk
- No re-embedding on app restart
- Can handle multiple policy documents in single collection
- DuckDB backend (embedded, no separate database)

### 5. **Hierarchical Parsing (Manual Regex)**
- Document has documented structure (7 sections × 7 subsections)
- Preserves section/procedure metadata
- Better than generic token-based splitting
- Allows cleanup of repeating headers/footers

### 6. **Streamlit UI**
- Minimal, focused interface
- Perfect for POC/demo
- Can be extended to FastAPI + React if needed
- Rapid development iteration

## 📊 Performance Expectations

### Ingestion (first run):
- PDF extraction: ~1 minute
- Chunk creation: ~2 minutes
- Embedding generation: ~5-10 minutes (includes model download)
- **Total: 8-20 minutes** (depending on hardware)

### Retrieval:
- Vector search: ~50ms
- BM25 search: ~10ms
- Re-ranking: ~5ms
- **Total: ~65ms**

### Generation:
- LLM inference: 5-30 seconds (depends on query length + hardware)
- **Total per question: 10-40 seconds**

### Storage:
- PDF text chunks: ~5-10MB
- Embeddings (1000 chunks): ~1-2GB
- ChromaDB index: ~200-500MB
- **Total: ~2-3GB** (varies with document size)

## 📞 Support & Troubleshooting

### Common Issues:

**"Cannot connect to Ollama"**
```bash
# Ensure Ollama is running:
ollama serve

# Verify the model is pulled:
ollama pull qwen2.5:14b-instruct

# Check connectivity:
curl http://localhost:11434/api/tags
```

**"PDF not found during ingestion"**
```bash
# Verify PDF path:
ls data/pdf/

# Update PDF_PATH in .env and src/ingestion.py if needed
```

**"Slow embeddings on first run"**
- Normal: sentence-transformers downloads model (~500MB) on first use
- Future runs use cached model
- Allow 10-15 minutes for first embedding run

**"ChromaDB collection is empty"**
```bash
# Run ingestion if not already done:
python src/ingestion.py

# Verify chunks exist:
ls -la chroma_storage/
```

**"Streamlit not opening"**
```bash
# Explicitly specify port:
streamlit run app.py --server.port=8501

# Then open: http://localhost:8501
```
