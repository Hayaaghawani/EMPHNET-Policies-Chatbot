I'm building a proof-of-concept RAG chatbot for a company (EMPHNET) that lets staff ask natural-language questions about an HR policy manual and get answers grounded strictly in that document, with citations.

Scope for this POC: one source document, Human_Resources_Policies___Procedures_Manual__ML-HR-01__V_01__docx.pdf (158 pages, mostly English with a few bilingual Arabic form attachments). Stateless, single-turn Q&A, local web demo — no auth, no persistent chat history, no Teams/SharePoint integration yet.

Document structure (already inspected, use this directly instead of generic clause-number regex):

7 top-level Sections (Section 01: Recruitment & Selection … Section 07: Personnel Management)
Each Section has subsections X.1 Purpose, X.2 Scope, X.3 Responsibilities, X.4 Policies, X.5 Procedures, X.6 Related Documents, X.7 References
X.4 Policies contains named policy topics (e.g., Sick Leave, Maternity Leave, Overtime) that should each be their own chunk
X.5 Procedures contains named procedures, each with a built-in reference code like ML-HR-01.P18 Leave Request and a Step/Action/Responsibility table — use this reference code as the citation ID for procedure-related answers
After the 7 sections: Annexes (Annex 0N) and Attachments (Attachment 0N), some bilingual (Arabic form titles)
Every page has repeating header/footer noise to strip before embedding: Global Health Development|Eastern Mediterranean Public Health Network (GHD|EMPHNET), ML-HR-01, V.01, Page X of 158, and a DocuSign Envelope ID: ... watermark line
Document-level metadata (manual code ML-HR-01, version 01, effective date August 7th, 2022) is on page 6 — extract once, apply to all chunks

Stack:

Python
LangChain for the RAG pipeline (loader → splitter → embeddings → vectorstore → retriever → prompt → LLM)
PyMuPDF (fitz) for PDF parsing
sentence-transformers with intfloat/multilingual-e5-large for embeddings, running locally (no API key)
ChromaDB (local, persistent) as the vector store
Ollama running qwen2.5:14b-instruct as the LLM (assume Ollama is installed and the model is pulled; if not, give me the exact ollama pull command to run)
Streamlit for the UI

Ingestion requirements:

Extract text with PyMuPDF, stripping the repeating header/footer/DocuSign watermark lines described above.
Parse hierarchically: Section → Subsection → (Policy topic | Procedure block | Annex/Attachment), using the regex patterns described above, not a generic clause-number splitter.
For X.5 Procedures blocks, try to extract the Step/Action/Responsibility table cleanly (try pdfplumber table extraction and compare against plain PyMuPDF text extraction — show me both so I can pick).
Attach metadata to each chunk: document title, manual code, version, effective date, section number + title, subsection number + title, procedure reference code (if applicable), page number, and a language field (mostly "en", but flag bilingual attachment chunks appropriately).
Store chunks + metadata + embeddings in a local Chroma collection, persisted to disk so I don't have to re-embed every run.

Retrieval:

Top-k similarity search (k=5), returned with metadata.
Also implement a simple keyword/BM25 pass I can compare against, since clause-number lookups ("what does section 4.2 say") benefit from exact match as well as semantic search — I want to see if hybrid retrieval meaningfully beats pure vector search on this document.

Generation:

System prompt that strictly grounds the answer in the retrieved chunks only, explicitly instructs the model to say "I couldn't find this in the policy manual" rather than guess if the retrieved content doesn't answer the question, and asks the model to answer in the same language the question was asked in (Arabic or English).
The answer must include: a plain-language response, the source document name, the section/clause number, and the verbatim excerpt(s) the answer was drawn from.

UI (Streamlit):

A single text input for the question, a submit button, and a results area showing: the generated answer, then below it a collapsible "Sources" section showing section number + excerpt for each retrieved chunk used.
Keep it minimal — this is a POC, not a polished product.
